SPRINT 9A — CONVERSATION INTAKE ENGINE

IMPORTANT:

This sprint is the highest priority.

Do not modify:

* Fleet Intelligence
* Purchasing Intelligence
* Executive Command Center
* Memory Systems

Use existing:

* Intent Engine
* Knowledge Base
* Customer Memory
* Vendor Memory
* Governance Engine
* AI Task Center

Goal:

AI must stop creating tasks immediately.

AI must:

1. detect intent
2. determine required fields
3. ask follow-up questions
4. collect missing information
5. remember previous answers
6. continue interrupted conversations
7. create task only after minimum data completeness is achieved

====================================================
PHASE 1 — DATABASE
==================

Create table:

conversation_intake_sessions

Fields:

* id
* company_id
* customer_id nullable
* vendor_id nullable
* phone
* intent_code
* category
* status

Allowed status:

* active
* waiting_user
* waiting_document
* completed
* cancelled
* expired

Fields:

* required_fields jsonb
* collected_fields jsonb
* missing_fields jsonb
* uploaded_documents jsonb
* confidence_score numeric
* completion_pct numeric
* needs_admin_review boolean
* ai_summary text
* last_message_at
* expires_at
* created_at
* updated_at

Indexes:

(company_id, phone)
(company_id, status)
(company_id, intent_code)

1. receive intent result

====================================================
PHASE 3 — FOLLOW-UP QUESTION ENGINE
===================================

AI must ask questions dynamically.

Example:

Intent:
cash_advance

Required:

amount
purpose
payment_method

User:

"Saya mau kasbon"

AI:

"Baik. Berapa nominal kasbon yang diajukan?"

User:

"500 ribu"

AI:

"Untuk keperluan apa kasbon tersebut?"

User:

"Bensin"

AI:

"Metode pembayaran yang diinginkan?"

Only after complete:

create task.

====================================================
PHASE 4 — COMPLETENESS RULES
============================

Create:

src/lib/intake-completeness.ts

Rules:

completion_pct =
collected_fields / required_fields

Threshold:

0–49%
Not Ready

50–79%
Continue collecting

80–100%
Eligible

Each intent may override threshold.

Example:

complaint:
60%

import:
90%

fleet_repair:
80%

cash_advance:
100%

====================================================
PHASE 5 — MEMORY INTEGRATION
============================

When session starts:

customer memory

vendor memory

Jakarta → Surabaya

AI:

"Saya lihat biasanya pengiriman dari Jakarta ke Surabaya. Apakah tujuan pengiriman kali ini sama?"

PHASE 6 — TASK CREATION CONTROL
===============================

CRITICAL

Task creation must move here.

Current:

message
→ intent
→ task

message

OR

admin forces create

====================================================
PHASE 7 — CONVERSATION RECOVERY
===============================

If user disappears.

Resume later.

Example:

Day 1:

"Saya mau trucking"

AI asks 5 questions.

User answers 2.

Session remains active.

Day 3:

User returns.

AI continues from remaining fields.

Do not restart conversation.

====================================================
PHASE 8 — EXPIRATION
====================

Session expiry:

24 hours default

After expiry:

status=expired

New message:

create new session

Preserve history.
