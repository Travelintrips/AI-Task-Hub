SPRINT 9C — DOCUMENT INTAKE & VALIDATION AI

Sprint 9A Intake Engine and Sprint 9B Mini Form Router are planned.

Now build Document Intake & Validation AI.

Goal:
When customer/vendor/admin uploads documents, AI must validate whether the document is correct, complete, and matches the required template before task is processed.

Documents include:
- Commercial Invoice
- Packing List
- BL / AWB
- HS Code
- COA
- MSDS
- photo damaged goods
- STNK / KIR / insurance
- fuel receipt
- maintenance invoice
- cash advance receipt
- vendor license documents

====================================================
B. DOCUMENT VALIDATION ENGINE
====================================================

Create:

artifacts/api-server/src/lib/document-validation-engine.ts

Responsibilities:
1. receive uploaded document
2. identify document type
3. load validation rules by document_type + intent_code
4. extract fields using OpenAI vision / OCR
5. compare extracted fields vs required fields
6. mark status:
   - valid
   - incomplete
   - invalid
   - needs_review
7. save audit record
8. return missing fields and issue summary

Important:
- If confidence < 0.65 → needs_review
- If required fields missing → incomplete
- If document type mismatch → invalid
- If valid → can be attached to intake/task

====================================================
E. INTAKE INTEGRATION
====================================================

When mini form uploads document:
1. save file
2. call DocumentValidationEngine
3. attach audit result to conversation_intake_sessions.uploaded_documents
4. update missing documents
5. if document incomplete:
   send WA:
   "Dokumen Packing List sudah kami terima, namun data gross weight dan volume belum terlihat. Mohon kirim ulang atau lengkapi data tersebut."
6. if valid:
   mark document complete
