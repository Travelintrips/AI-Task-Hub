====================================================
C. MODULE 2 — DUPLICATE PURCHASE DETECTION
====================================================

Detect duplicate logistic purchase requests.

Compare against:
- logistic_purchase_requests
- vendor_invoices
- vendor_payments
- expenses
- purchasing_signals

Similarity factors:
- same vendor
- same service category
- similar amount ±15%
- same origin/destination
- same logistic_order_id
- same month
- same invoice number if available

Write result to:
- purchasing_intel_signals
- logistic_purchase_requests.ai_duplicate_flag
- logistic_purchase_requests.ai_duplicate_of_id

API:
POST /api/purchasing/requests/:id/check-duplicate
GET /api/purchasing/duplicates

====================================================
D. MODULE 3 — PURCHASE REQUEST INTELLIGENCE
====================================================

Create request flow:

POST /api/purchasing/requests
GET /api/purchasing/requests
GET /api/purchasing/requests/:id
GET /api/purchasing/requests/:id/intel
POST /api/purchasing/requests/:id/evaluate
PATCH /api/purchasing/requests/:id/status

When request is created:
1. Save request
2. Run price benchmark
3. Run duplicate check
4. Create purchasing_intel_signals
5. Calculate aiRiskScore and aiRiskTier
6. Do not approve automatically

Risk scoring:
- priceDeviationScore 25%
- duplicateScore 25%
- vendorRiskScore 20%
- budgetImpactScore 15%
- marginImpactScore 15%

Tier:
0–30 LOW
31–60 MEDIUM
61–80 HIGH
81–100 CRITICAL
